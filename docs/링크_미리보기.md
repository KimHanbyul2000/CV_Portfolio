# 링크 미리보기 (내부)

링크를 카카오톡·슬랙·링크드인·지원서 등에 붙였을 때 뜨는 **제목·설명·이미지 카드**가 어떻게 정해지는지,
이 저장소에서 무엇을 해 두었고 무엇은 사람이 직접 해야 하는지 적는다.

## 한 줄 요약

| 공유하는 주소 | 미리보기를 정하는 것 | 설정 필요? |
|---|---|---|
| `kimhanbyul2000.github.io/CV_Portfolio/` (홈페이지) | `index.html` 의 `og:` 태그 | **아니오 — 이미 되어 있다** |
| `kimhanbyul2000.github.io/` (사용자 사이트) | 그 저장소 `index.html` 의 `og:` 태그 | **아니오 — 이미 되어 있다** |
| `github.com/KimHanbyul2000/CV_Portfolio` (저장소) | GitHub 저장소 설정의 **Social preview** | **예 — 웹 화면에서 직접 올려야 한다** |

지원서·메시지에는 **홈페이지 주소**를 넣는다. 저장소 주소보다 준비된 미리보기가 뜬다.

## 1. 미리보기 이미지 (`assets/img/og.png`)

| | |
|---|---|
| 크기 | 1200 × 630 px (가로:세로 ≈ 1.91:1 — 대부분의 앱이 권장하는 비율) |

## 2. HTML 의 `og:image` (자동으로 동작하는 부분)

`og:` 태그는 **Open Graph** 라는 규약이다. 링크를 받은 앱이 그 페이지를 직접 읽어서 `<head>` 안의 이
태그들을 찾고, 그 값으로 카드를 만든다. 페이지에 태그만 있으면 **앱 쪽에서 따로 설정할 것은 없다.**

이 저장소 `index.html` 의 `<head>`:

```html
<meta property="og:type" content="website">
<meta property="og:title" content="Kim Hanbyul — Biomedical × Semiconductor × Medical AI → Neuromorphic">
<meta property="og:description" content="바이오메디컬 × 반도체 × 의료 AI에서 뉴로모픽 반도체로 — 3D 곡면으로 보는 커리어 경로">
<meta property="og:url" content="https://kimhanbyul2000.github.io/CV_Portfolio/">
<meta property="og:image" content="https://kimhanbyul2000.github.io/CV_Portfolio/assets/img/og.png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta name="twitter:card" content="summary_large_image">
```

| 태그 | 역할 |
|---|---|
| `og:title` / `og:description` | 카드의 제목·설명 |
| `og:url` | 이 페이지의 대표 주소 |
| `og:image` | 카드 이미지. **반드시 `https://` 로 시작하는 절대 주소** — 앱은 페이지 밖에서 이미지를 가져가므로 `assets/img/og.png` 같은 상대 경로는 못 읽는다 |
| `og:image:width` / `height` | 이미지를 받기 전에 카드 크기를 잡는 힌트 |
| `twitter:card` | X(트위터) 등에서 큰 이미지 카드로 보이게 |

사용자 사이트(`KimHanbyul2000.github.io/index.html`)에도 같은 태그가 있고, 제목·설명만 그 사이트 것이다.
이미지는 이 저장소의 `og.png` 를 절대 주소로 가리킨다 — **`og.png` 의 경로나 이름을 바꾸면 사용자 사이트도
같이 고친다.**

### 캐시 — 바꿨는데 예전 카드가 뜰 때

앱은 한 번 읽은 미리보기를 한동안 저장해 둔다. 이미지·문구를 바꿔도 **이미 공유된 적 있는 주소**는 예전
카드가 뜰 수 있다. 시간이 지나면 새로 읽는다. 바로 바꾸려면 각 서비스의 도구로 다시 읽게 한다(해당
서비스 로그인 필요):

| 서비스 | 도구 |
|---|---|
| 카카오톡 | 카카오 개발자 사이트의 "공유 디버거" — 주소 입력 후 캐시 초기화 |
| 링크드인 | LinkedIn "Post Inspector" |
| 슬랙 | 별도 도구 없음. 시간이 지나면 갱신된다 |

## 3. 저장소 Social preview (사람이 직접 해야 하는 부분)

`github.com/KimHanbyul2000/CV_Portfolio` 처럼 **저장소 주소**를 공유하면, 위의 `og:` 태그는 쓰이지 않는다.
그 주소는 GitHub 의 페이지라서 GitHub 이 자기 카드(저장소 이름·설명·언어 통계로 자동 생성)를 보여준다.
여기에 우리 이미지를 쓰려면 저장소 설정에서 올려야 한다.

1. https://github.com/KimHanbyul2000/CV_Portfolio 에서 **Settings** (저장소 소유자만 보인다)
2. **General** 페이지 중간의 **Social preview** 항목
3. **Edit → Upload an image…** 에서 이 저장소의 `assets/img/og.png` 를 고른다
4. 올리면 바로 저장된다. 지우려면 같은 곳에서 **Remove**

- 이 설정은 **웹 화면에서만** 할 수 있다(GitHub CLI·API 로는 못 올린다). 그래서 Claude 가 대신하지 않았다.
- GitHub 권장 크기는 최소 640×320, 1280×640 이 가장 잘 맞는다. `og.png`(1200×630)도 비율이 거의 같아 그대로 쓸 수 있다.
- 사용자 사이트 저장소(`KimHanbyul2000.github.io`)도 저장소 주소를 공유할 일이 있으면 같은 방법으로 따로 올린다.

## 확인 방법

```bash
# 이미지가 공개 주소에서 열리는지 (200 이면 정상)
curl -s -o /dev/null -w "%{http_code}\n" https://kimhanbyul2000.github.io/CV_Portfolio/assets/img/og.png

# 배포된 페이지에 og:image 태그가 들어갔는지
curl -s https://kimhanbyul2000.github.io/CV_Portfolio/ | grep 'og:image'
```

실제 카드 모양은 자기 자신에게 카카오톡·슬랙 메시지로 주소를 보내 보면 확인된다.
